This guide defines the standards for the `ucp-sdk` Python package, focusing on type-safe, idiomatic, and agnostic commerce integration.

## Core Principles

### 1. Brand Neutrality
*   **DO NOT** use brand names (e.g., Target, Shopify) in code, comments, or documentation.
*   **DO** use role-based terms: `Merchant`, `Provider`, `Agent`, `Buyer`.

### 2. Type Safety and Validation
*   **Pydantic:** Mandatory use of Pydantic v2 for all data models and API payload validation. Use `TypeAdapter` for validating complex nested structures.
*   **Type Hinting:** Required for all function signatures and public class attributes.
*   **Email Validation:** Use `pydantic[email]` or `email-validator` for any email fields.

### 3. Pythonic Idioms
*   **Formatting:** Enforced via Ruff. Note the repository-specific **2-space indentation**.
*   **Docstrings:** Use Google Style docstrings for all public modules, classes, and functions.
*   **Async:** Use `asyncio` for non-blocking I/O operations where performance is critical.

## Technical Standards

### Python Code Style
*   **Linter:** Ruff is the primary linter and formatter (configured in `pyproject.toml`).
*   **Line Length:** Hard limit of **80 characters**.
*   **Quotes:** Use double quotes (`"`) for strings.
*   **Imports:** Use `isort` (via Ruff) to maintain consistent import ordering.

### Repository Specifics
*   **Generated Code:** The `datamodel-codegen` is used to generate models from JSON schemas. **Do not manually edit** files marked with the "generated by datamodel-codegen" header.
*   **Testing:** Use `pytest` for all unit and integration tests.
